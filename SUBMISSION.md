## Submission description

### One line

Sitr tells you, in Arabic or English, whether something is safe to share with an AI
assistant, and hands you a version that is.

### Short (about 100 words)

People paste CVs, contracts and code into AI chatbots every day, often without noticing the
names, IDs, salaries and keys inside. Sitr (ستر, "cover") is a bilingual gate you ask first:
"Can I send this to an AI assistant?" It checks the text or file with deterministic rules and
two Hugging Face models running inside the app, then answers yes or no in plain words, says
what it found, and gives you the safe version: redacted text to copy, or a redacted PDF.
Secrets are blocked and never reach a model. Built on Gradio, Transformers and the Hugging Face
Hub, with a synthetic Arabic-English dataset generated in a Hugging Face Job.

### Full

**Problem.** Employees in Qatar and across the Gulf use AI assistants for real work, in Arabic,
English and both at once. A CV, an employment contract or a snippet of code can carry a Qatar
ID, a salary, an IBAN or a live API key. Most data-loss tools are English-first, built for
security teams, and say "blocked" without telling the user what to do instead.

**What Sitr does.** You ask Sitr before you ask the assistant. Type or paste text, or attach a
PDF, code or text file, and ask "Can I share this?" Sitr gives one of four answers:

| Answer | When | What you get |
|---|---|---|
| Safe | Nothing personal, confidential or secret | The text, ready to paste |
| Needs changes | Personal data such as names, emails, phones | A redacted version (`[EMAIL_1]`), or a redacted PDF |
| Keep private | Confidential details such as salaries and IDs | Advice to keep it private, and a redacted version if you still want to ask |
| Don't send | Secrets such as API keys and passwords | A version with the secret removed, and a reminder to rotate it |

Developer details (risk score, reason codes, the highlighted findings) stay one click away under
"See what I found". Small talk ("hello", "what can you do?") gets a short reply from Qwen, but
only after the check finds nothing sensitive.

**How it works.**

1. **Rules** catch structured secrets and identifiers in Arabic and English: API and cloud keys,
   passwords, private keys, JWTs, Qatar IDs, IBANs, card numbers, salaries, emails and phones.
2. **`OpenMed/privacy-filter-multilingual-v2`** finds names and personal data the rules cannot.
3. **`Horizon-Labs/multilingual-zeroshot-small`** reads what the text is about (HR, legal,
   source code) to catch confidential content with no single sensitive token.
4. **A policy engine** combines them. Deterministic rules always win over model guesses, and a
   critical secret never reaches any model.
5. **`Qwen/Qwen2.5-1.5B-Instruct`** answers allowed small talk through Hugging Face Inference
   Providers, and runs inside the app for the private route.

Redacted PDFs are rebuilt with PyMuPDF and then read back: if any found value survives in the
page text, metadata, outline, links or attachments, the PDF is refused.

**Use of Hugging Face.** Spaces hosts the app. Three Hub models do detection, classification and
answers; the two detectors run on CPU inside the Space, so no text leaves it to be checked. The
synthetic dataset [`arwaili/sitr-synthetic-dlp`](https://huggingface.co/datasets/arwaili/sitr-synthetic-dlp)
(300 Arabic, English and mixed examples) was generated by Qwen in a Hugging Face Job and is
published on the Hub with dev and test splits.

**Results** (held-out test split, full pipeline):

| Measure | Result |
|---|---|
| Correct action (allow, redact, private, block) | 0.95 (English 1.00, Arabic 0.90, mixed 0.95) |
| Entities, precision / recall | 0.968 / 0.938 |
| Names (OpenMed), precision / recall | 0.900 / 0.931 |
| Time on the Space (2 vCPU) | block about 2 s, redact 5-8 s |

The dataset is template-based, so real documents will score lower. An adversarial review by the
team found and fixed three leaks before submission (a file name kept in downloads, values in PDF
metadata, and a name missed when the question was checked together with the content), each now
covered by a regression test, among 306 automated tests.

**Safety.** Synthetic data only. Sitr is decision support, not a compliance guarantee; the
private route is a demonstration, not an isolated environment. Sitr never logs the text it
checks, the values it finds, or the replacements it makes.

**Built with:** Python 3.11, Gradio 6, Transformers, Hugging Face Hub and Inference Providers,
Pydantic v2, PyMuPDF, Pytest, Ruff, GitHub Actions.

## 90-second demo script

Open the Space before the demo and wait until the sidebar says **Privacy detector ready**. Use
the four example cards; they hold synthetic data.

| Time | On screen | Say |
|---|---|---|
| 0:00-0:10 | The welcome screen | "This is Sitr, ستر. Before you paste something into an AI assistant, you ask Sitr first." |
| 0:10-0:30 | Click **Can I share this CV with an AI assistant?** | "A CV with a name, email and phone. Sitr says not as it is, tells me exactly what it found, and gives me this version with placeholders, ready to paste." Hover the box and click **Copy**. |
| 0:30-0:45 | Click the reset arrow (top right), then **Can I ask an AI to fix this code?** | "Code with an API key. That's a secret, so the answer is don't send, and the key never reaches any model. I still get a version with the secret removed." Open **See what I found** to show the highlight. |
| 0:45-1:05 | Reset, press **العربية**, click the contract card | "Everything works in Arabic, right to left. An employment contract with a salary and a Qatar ID: keep it private." |
| 1:05-1:20 | Reset, type **hello! what can you do?** | "It also talks, but only after checking. Nothing sensitive here, so Qwen answers." |
| 1:20-1:30 | Open **Dashboard** | "Every decision is counted, but never the text itself. Rules plus two Hugging Face models inside the app, Qwen for answers, on a public Space." |

If the Space is slow, play the backup video. The safety answers take 2-8 seconds; the Qwen reply
can take up to 20.

## 3-minute pitch

**0:00 The problem (30 s).**
"Every day, people paste real work into AI assistants: a CV to improve, a contract to translate,
code to fix. Inside are names, Qatar IDs, salaries, bank accounts and API keys. Once sent, you
can't take it back. And here, that work is in Arabic, English, or both in one sentence, which
most data-protection tools don't read well."

**0:30 The idea (20 s).**
"Sitr, ستر, means cover. It is the step before the AI: you ask Sitr 'can I send this?', and it
answers like a careful colleague would. Yes. Not like this, send this instead. Keep it private.
Or don't send it at all."

**0:50 Demo (60 s).**
Run the CV, the code with the key, and the Arabic contract from the demo script.

**1:50 How it works (35 s).**
"Three layers. Deterministic rules catch keys, IDs, IBANs and salaries in both languages. The
OpenMed privacy model finds names. A zero-shot classifier reads what the text is about. A policy
engine decides, and rules always beat model guesses, so a secret can never slip through to a
model. The two detectors run inside the Space; nothing leaves it to be checked. Qwen answers
only what has already passed."

**2:25 Proof (20 s).**
"We generated a 300-example Arabic-English dataset with Qwen in a Hugging Face Job and published
it. On the held-out test set Sitr picks the right action 95% of the time. We attacked our own
app, found three leaks, fixed them, and locked each with a test."

**2:45 Close (15 s).**
"Sitr is live on Hugging Face Spaces today. Next: a browser extension that checks text before it
reaches any chatbot, and company policies in the same engine. Ask Sitr first."
